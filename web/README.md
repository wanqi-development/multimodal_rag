# 前端（P1：检索 / 问答 / 引用看原文）

Vue 3 + TypeScript + Vite。**没有引 UI 组件库**（要表格/抽屉/上传时再上 Naive UI 或 Element Plus）；
答案的 markdown 也是自己渲染的（`src/markdown.ts`，零依赖、只认常用语法，先转义再拼标签）。

一处例外：**内联 HTML 表格**（PDF 走 OCR 出来的表格就是 HTML，见 `cleaning.py` 的说明）。
渲染时整块 `<table>…</table>` 交给 `safeTable` —— 先用 `DOMParser` 解析、**再按白名单重建**
（只留表格结构标签与 `rowspan/colspan/align`），不是直接放行一段 HTML。

**有序列表保留首项编号**（`<ol start="N">`，N>1 时才输出）：列表被正文段落打断时每一段都是
独立的 `<ol>`，浏览器会各自从 1 数起 —— 实测文档里 `1./2./3.`（中间夹着正文）显示成了
`1./1./1.`。连续写 `1./1./1.` 的惯用写法首项是 1、不输出 start，仍按 1./2./3. 数。

## 跑起来

```powershell
# 终端 1：后端
rag serve                       # 127.0.0.1:8000

# 终端 2：前端（开发模式，带热更新）
cd web
pnpm.cmd install                # 注意用 .cmd：这台机器的 .ps1 被执行策略挡着
pnpm.cmd dev                    # http://127.0.0.1:5174
```

开发期走 **Vite 代理**（`vite.config.ts` 里列了后端那几条路径）→ 后端不用加 CORS。
监听地址可用仓库根 `.env` 的 `RAG_WEB_HOST` / `RAG_WEB_PORT` 覆盖；
直接 `cd web && pnpm dev` 也会读取这份根 `.env`。
生产构建 `pnpm.cmd build` 产出 `web/dist/`，`rag serve` 会**自动把它挂到 `/`**（见 `api/app.py`），
那时一个进程就够了。

## 鉴权

页面右上角填 `RAG_API_KEY`（存在 localStorage）。**留空 = 只允许本机**，本机开发可以直接空着。

## 一个关键实现选择

**流式用 `fetch` + `ReadableStream` 读 SSE，不用 `EventSource`** —— `EventSource` 不能自定义
请求头，而 `/chat`、`/agent` 都要 `X-API-Key`。用 `fetch` 还能 abort（页面上的「停止」按钮
直接触发后端那套断线取消）。

## 「会话」没有独立页 —— 它并进了对话页

**2026-10-08 使用者问「会话和对话列表是不是重复了」，核下来确实重复**：对话页顶部的
「会话 N」下拉已经有**列表 + 点开回放（`openSession`）+ 每轮的 token 账 + 中断那一轮的
批准卡片 + 删除 + 新对话**，我原本要做的会话页基本是这些的翻版。所以**不做独立页**

**2026-10-08 又改了一次**（使用者定：会话不要顶部按钮、竖着放左侧一列）：下拉删掉，
改成对话页内**左侧一列会话列表**（对话区在右）。两个栏都能收起、会话栏宽度可拖：

* 导航栏收起 → 60px 只剩图标（**按钮在导航栏最上面**、品牌行右侧，图标 `sidebar-close / sidebar`，

还留在 CLI / 没有入口的两小块：「批量清理」与「总账」

## 「评测」也没有页面 —— 它留在 CLI

**2026-10-08 使用者定：评测不做管理台页面。** 评测要的是「定一份 golden set、跑一遍、
对比两次的数字」，它是一次性的批处理，不是天天点的界面；而且跑一次要过线上模型（按量计费），
挂在页面上反而容易被误点。所以导航里那一项（原来标着 `soon: P3`）、占位页
（`PlaceholderView.vue`）与页面枚举里的 `eval` 一并删掉了，要跑评测走 CLI：

```bash
rag eval --label baseline --top-k 8            # 基线：指标看报告
rag eval --label b --judge --ragas             # 多算引用准确率与 ragas
```

评测那套代码（`src/rag/eval/`）与文档（`docs/architecture.md` §13）**都还在**，
删掉的只是前端那一页 —— 它从来没有实现过，只是导航里一个「计划中」的占位。

## 文档页的两条纪律（`src/views/DocumentsView.vue`）

* **正文只读**。预览是解析稿，页面上没有任何入口改它；能改的只有「第几行是几级」这一列
  （标题清单）。正文一改，偏移 → 页码/行号就错位，「点引用看原文」就废了。要改内容请改
  源文件后重传。
* **慢步骤走 202 + 轮询 `/jobs`**。解析（OCR/VLM）是分钟级，卡在一个请求里既看不到进度、
  又会被中间层掐断。

层级编辑**嵌在文档里**：左边是解析稿，标题行就地一个层级下拉 + 「标为正文」按钮；
**右边是原文**。原著 PDF 由浏览器内置查看器渲染（**上下连续滚动、不分页**），
HTML 走沙箱 iframe、图片给 `<img>`、纯文本放 `<pre>`。

**不做映射**（2026-10-08 使用者定的）：点左边不会跳右边、没有高亮框 —— 上一版做过
「按页渲染 + 框住那一块」，当天撤掉了。后端的 `/page/{n}` 与 `/locate` 还留着（有测试），
页面暂时不调；要捡回来只要重写右栏这一段。

对比框嫌小就点工具栏上的**「全屏对比」**（再点一次或按 **Esc** 退出）：工具栏 + 两栏一起
铺满窗口。它是 `position: fixed` 换定位、**不改 DOM**，所以左边已选的层级与没提交的改动
都不会丢，**提交按钮也在全屏里**；全屏时两栏各自撑满高度、内部滚动，原文那一栏因此是整屏上下滑。

「标为正文」= 层级写 0：解析常把一段普通文字认成标题，而删行不行（清单必须与正文的标题行
一一对应，少一行整份就切不了），所以改的是它的角色 —— 那行原文（含 `#`）留在正文里，
只是不再单独成节。

## 右栏是「主流程 + 阶段面板」

上边是流程图（`components/FlowSteps.vue`）：没到的节点灰、到了的蓝、**进行中一个半蓝半灰
转起来的圆环**（CSS `conic-gradient`，不引 UI 库）。点已完成的节点能回去看那一步的结果。
「进行中」不是本地状态 —— 它来自 `GET /jobs` 按 `request.doc_id` 认出这份文档正在跑哪一步，
所以**刷新页面照样认得出来**。

下边跟着流程图换（`DocumentsView.vue`，块级明细与图表在 `components/ChunkReport.vue`）：

* **上传 / 导入**：大小、哈希、落盘时间、来源，以及**原文** —— HTML 走沙箱 iframe
  （`sandbox=""`，脚本与表单都关掉）、PDF 交给内置查看器、纯文本放 `<pre>`。
* **解析**：跑的时候循环「解析中…」；完成后给字数/图片/解析器/耗时与解析稿，
  取不到的图会**一直列在面板上**（不是导入时闪一下）。
* **核对标题**：左右对比（见上）。
* **拆分并入库**：跑的时候循环「拆分入库中…」；完成后给块数、块大小分布条、大纲树、
  产物大小、向量占用估算，以及**产物块数和 Milvus 注册表对不对得上**。

`.stale`（产物过期）会明确写出「源文件的哈希变了」并给出两个哈希 —— 步骤灯回退时让人
一眼知道是源文件换了，而不是自己点错了。

阶段做完后**主按钮会置灰**（「✓ 已解析」「✓ 已拆分并入库」），重跑走旁边小号的
「重新解析」「重新入库」—— 亮着的按钮会让人以为还得再点一次。

任务完成后页面靠什么刷新：**不是**等任务状态从 running 跳成 done（后台标签页的定时器会被
浏览器降频到一分钟一次，那一瞬间就错过了），而是每次轮询比「这份文档最近一次任务的时间戳
vs 手上这份详情的时间戳」，新了就重拉；切回标签页时再立刻对齐一次。

左侧是**文档树**（2026-10-08 从平铺列表改过来）：人工目录最多三层，目录行 hover 出
「新建子目录 / 改名 / 删除」，文档行勾选后用顶上的「移动到…」下拉批量挪，**也可以直接
把文档行拖到目录行上**（拖的那条在勾选里就整批一起走；「未分类」那一格也是落点）。
目录是**虚拟的**：后端只在 `data/uploads/_folders.json` 里记归属，不改 doc_id、不挪文件、
不碰 Milvus（理由见 `docs/architecture.md` §12.20）。树**默认全展开**，顶部那条上传/导入
旁边能选「放进哪个目录」。

另一棵树用在「拆分并入库」之后的章节列表上：
后端的 `heading_path` 是从根到该节的完整路径，按 ` -> ` 拆开就能还原层级，渲染时按深度
缩进 —— 父节点自己没有正文是正常的（标题下面直接跟更深的标题），那种行显示 `—`。
**默认全折叠**，点行首箭头展开（668 节那种树全摊开没法看）。
带子节点的行会写一行「含子项 N 块 / M 字」—— 折叠状态下靠它看出整章多大
（很多父节点自己没有正文，块/字列是 `—`）。

核对那一步的左侧**按 markdown 渲染**：标题字号跟当前选的层级走，标为正文的按正文渲染，
层级下拉与「标为正文」收在行尾、平时半透明 —— 左边看起来就该是那份文档本身。

## 文档从哪来：上传 / 链接两种

「从链接导入」把 URL 交给后端去抓（`POST /documents/fetch`）—— 链接指向的可能是 HTML
文档页，也可能是 PDF / Word 的下载链接，类型由后端判定。抓回来与上传件**完全同构**：
落盘名是 `<真名>-<内容哈希><扩展名>`，页面显示真名（`display_name`）。

抓的是 HTML 时，**页面里的图片会一起抓下来**（落在同级的 `<真名>-<页面哈希>_files/`
目录），解析时它们就成了正常的图片块（和 PDF / Word 那些一样有 VLM 描述、能按图检索）。
没抓到的图（外链、防盗链、`.svg` 图标）不会让这次导入失败，但会在提示条里**逐条说明**
—— 少几张图会让检索结果悄悄变差，那种沉默最难查。

所以**同一份内容重复导入是幂等的**（同一个 doc_id，原地更新）；而**同名但内容不一样**
时后端不覆盖，返回里带 `conflicts`，页面弹一条确认：覆盖更新（会连旧版的解析产物与
已入库内容一起清掉，不可逆）还是保留两份。
