# 引用格式规范

## 什么时候用

每次要输出**带论断的答案或报告**时（也就是绝大多数回答）。纯聊天、澄清问题不用。

## 规则

1. **每条论断后面跟 `[n]`**，`n` 必须是工具返回里给你的编号 —— 不要自己编号，
   也不要引用工具没给过的号。一个编号可以支撑多句话，但一句话里的每个事实都要有出处。
2. **推断要标出来**：从多条材料推出来的结论，写「由此可以推断…」并附上涉及的那几个编号。
3. **资料不足就拒答**：写「已有的资料无法确定」，并说清缺的是哪一部分。
   **拒答时不要列出无关材料当引用** —— 那些片段不支持任何论断，只会把引用准确率拉低
   （实测：一条拒答案列 8 条无关引用，把「按引用条数」的口径从 90% 拖到 69%）。
4. **同一来源重复出现就用同一个编号**（工具已经这么发了，你直接复用即可）。
5. 给报告时会附一段「来源」清单：**只列答案里真的引用到的那些**。

## 例子

好：

```
Flink 通过 Save Points 把任务快照存在存储介质上 [3]，重启时可以从快照恢复计算状态 [3]。
资料里没有说 Save Points 的默认存储位置 —— 这一点无法确定。
```

不好：

```
Flink 的 Save Points 存在本地磁盘（没给编号）、默认每 5 分钟一次（编的）、
相关资料有 [1][2][3][4][5]（列了一堆没用到的）。
```
